## Claims we intend to test (each needs a figure or table)
1. **The best configuration is corpus-dependent.** Using one global config costs measurable
   regret. *(Oracle tables per corpus; fixed-choice regret.)*
2. **Label-budget curve**: how many labelled queries are needed to pick a config statistically tied with the best. *(Curves per corpus.)*
3. **LLM-judge selection**: the strict-relevance judge recovers the oracle ranking with no labels,
   worth the equivalent of N labels. *(Equivalent-label table: judge × mode × n.)*
4. **Chunk-level judge accuracy ≠ selection quality**: graded "partial credit" scoring
   rewards document hits and can invert the ranking for strong judges. *(Pilot shows this; must hold on the full grid.)*
5. **Synthetic questions**: naive synthetic QA (RAGAS-like) vs style-matched, and the lexical bias they introduce.
6. **Cost**: GPU-seconds per selection for each method.

## Threats to validity to address in the paper
- LegalBench-RAG gold spans are incomplete for some queries: report judge "false positives" that are actually relevant (manual audit of ~100 pairs).
- ContractNLI has many tied configs: report tie-set metrics, not only top-1.
- Judges and generators come from the same model family (Qwen): add Gemma as a second family.
- Synthetic questions generated by the same LLM that judges: keep generator ≠ judge in at least one setting.
